## Summary

- Add five language-agnostic maintainability rules to the shared rule base — comments restating code, dead code, bandaid fixes, speculative abstraction / over-configuration, and naming/size drift — all owned by a new `maintainability-assistant`.
- Ship them as a new rule guide plus a matching agent, so the Doc ↔ Agent Alignment rule holds and full mode can dispatch the owner.
- Scope the five rules' triggers to file types no language rule family owns — Terraform/IaC, shell, and other non-Go/Python/Node source extensions — so a language-only diff never puts a maintainability rule in the candidate set, and a mixed diff confines each finding to the non-owned file.
- Change no command and no existing rule. The only script edit is a trigger-boundary assertion in the acceptance suite, and the rule index is regenerated by the existing walker.
- Lock the dedup boundary with a committed fixture pair and that acceptance assertion, so the precommit gate fails if a future edit points a maintainability trigger at a language-owned extension.

## Problem

Verified on `bborbe/coding` `origin/master` (`v0.60.1`, 2026-10-18):

- 194 rules: 103 judgment, 75 mechanical, 16 script.
- 161 of the 194 are owned by a `go-*`, `python-*` or `node-*` assistant, and 81 of the 103 judgment rules are language-owned. No rule carries a `.tf`, `.tfvars`, `.hcl`, `.sh`, `.bash` or `.zsh` trigger glob.
- Running the exact Step 4b-i selector from `commands/pr-review.md` over a diff of `infra/main.tf`, `scripts/deploy.sh` and `README.md` yields 8 candidates: three commit rules, one markdown rule, one README rule, two `go-security` invariants that fire on `@commits`, and one self-containment rule. Zero are maintainability rules.
- The selector's `.trigger == null` clause makes a trigger-less judgment rule an always-candidate, but exactly one judgment rule is trigger-less (`git-workflow/never-direct-commit-to-master`), so that clause is not a coverage path for other languages.

A Terraform, shell or other non-Go/Python/Node change therefore reaches Step 4 with no maintainability rule to adjudicate. The mechanical funnel contributes nothing either — the ast-grep detectors are Go/Python/Node-specific — so the review's only judgment on such a diff comes from the commit-message and README rules. This is the gap the `maintainability-review` lens of the [[Five-Lens Review Gate]] fills, and it is the last unshipped item on [[PR Reviewer Adopts What the Five-Lens Gate Got Right]] (SC5). The task's scope is everything outside Go/Python/Node, so the trigger list names the common non-owned source extensions rather than only the Terraform and shell cases the goal names.

## Goal

The rule base carries five language-agnostic maintainability rules, all judgment-tier and owned by `maintainability-assistant`, that fire on Terraform, shell and other non-Go/Python/Node files — over the changed files in `/coding:pr-review` and `/coding:local-review`, and over the codebase's files in `/coding:code-review`.

A Terraform/shell fixture diff carrying a comment that restates the code, a dead declaration and a `|| true` bandaid produces all three findings, each tagged with the matching rule id and a valid citation. The same comment placed in a `.go` file produces no maintainability finding, because the Go rule family owns that file — a Go fixture hitting `go-errors/no-fmt-errorf` produces one finding, not two. A clean non-owned fixture produces zero maintainability findings.

The change is rules-plus-docs plus one acceptance assertion: no command and no existing rule is edited. The bench re-run after the change scores precision at or above the recorded SC4 baseline and adds no unadjudicated maintainability finding.

## Non-goals

- Do NOT add a language-specific Terraform or shell rule set — the five rules are language-agnostic; a Terraform-specific family is a separate task.
- Do NOT trigger on `.md` — the five smells are code/config smells, and docs already carry `markdown-todo/*`, `readme/*`, `claude-md/*`, `changelog/*` and `self-containment/*` rules.
- Do NOT trigger on `.yaml` or `.yml` — `k8s/**/*.yaml` is owned by `k8s-manifest/*`, and `.golangci.yaml` / `.golangci.yml` are owned by `go-linting/*`. A broad YAML glob would put maintainability rules and those families in the same candidate set, which is exactly the overlap this spec's dedup invariant forbids. CI and Helm YAML are out of scope for this change.
- Do NOT trigger on `.go`, `.py`, `.ts`, `.tsx`, `.js`, `.jsx`, `package.json`, `go.mod`, `go.sum`, `Makefile`, `Dockerfile`, `README.md`, `CHANGELOG.md`, `CLAUDE.md`, `agents/**/*.md`, `commands/**/*.md`, `skills/**/*.md`, `tsconfig.json`, `pyproject.toml` or `.golangci.yml` — those keep their existing owners, which is the dedup guarantee.
- Do NOT add mechanical (ast-grep) detectors — all five rules are judgment-tier; no `rules/maintainability/` YAML.
- Do NOT change `commands/pr-review.md`, `commands/local-review.md`, `commands/code-review.md`, `docs/selector-mode-guide.md`, `scripts/rule-checks.sh` or `scripts/validate-citations.sh`.
- Do NOT add a config knob, opt-out flag or config-level severity mapping — the rule `level` is the only acceptance surface, and the owner agent assigns the report's Must Fix / Should Fix / Nice to Have buckets as every existing owner agent does.
- Do NOT add a scenario file — committed fixtures plus a live review exercise are the proof.

## Desired Behavior

1. **The guide exists and carries five rule blocks.** `docs/maintainability-review-guide.md` ships `### RULE maintainability/<slug> (SHOULD)` blocks for `comment-restates-code`, `dead-code`, `bandaid-fix`, `speculative-abstraction` and `naming-size-drift`, each conforming to `docs/rule-block-schema.md` (Owner → Applies when → Enforcement → Trigger → Why, then `#### Bad` / `#### Good` examples using generic domains). The guide states what the lens judges, that it excludes correctness, and that it is language-agnostic by construction: the rules name no language, and the trigger list is the only place a file type appears.

2. **The five rules judge the lens's five smells.** Every rule's `Applies when` scopes it to a changed file whose type has no dedicated rule family, and names the smell in language-neutral terms:
   - `maintainability/comment-restates-code` — a changed comment restates the adjacent statement in prose ("increment the counter", "return the result") instead of explaining why the code does it.
   - `maintainability/dead-code` — a changed definition, branch or file has no reference anywhere in the repository, and the change does not state why it is retained.
   - `maintainability/bandaid-fix` — a changed line suppresses a symptom rather than the cause: a special-case branch, a retry/sleep, a widened type, an ignore directive, or a `|| true`-equivalent, with no stated reason.
   - `maintainability/speculative-abstraction` — a changed file adds an indirection with no second user: an interface with one implementation, a parameter every caller passes the same value for, a config field nothing reads, an abstraction for a use case absent from the change.
   - `maintainability/naming-size-drift` — a changed definition's behaviour no longer matches its name, or a unit has grown past the scope its name states (a "getter" that writes, a "validator" that mutates, a "parse" that fetches).

   Each rule's `Enforcement` is `judgment — <how the adjudicator decides>`, so `build-index.py` derives `enforcement_type: judgment`. Each finding must cite a real `file:line` on a changed line. The guide reuses `docs/code-smell-vocabulary.md`'s terms where they exist (`dead code`, `speculative generality`) and states why `dead-code` is judgment-tier here: the mechanical detectors (`vulture`, `ts-prune`) run only on Python and Node, so on a non-owned file the reachability judgment has no mechanical owner.

3. **The trigger list is the dedup boundary.** All five rules carry the same `**Trigger**:` line, comma-separated, exactly these 22 globs:

   `**/*.tf, **/*.tfvars, **/*.hcl, **/*.sh, **/*.bash, **/*.zsh, **/*.rb, **/*.java, **/*.kt, **/*.rs, **/*.c, **/*.h, **/*.cc, **/*.cpp, **/*.hpp, **/*.cs, **/*.php, **/*.swift, **/*.scala, **/*.lua, **/*.pl, **/*.sql`

   A file type owned by an existing rule family is deliberately absent: `.go`, `.py`, `.ts`, `.tsx`, `.js`, `.jsx`, `package.json`, `go.mod`, `go.sum`, `Makefile`, `Dockerfile`, `README.md`, `CHANGELOG.md`, `CLAUDE.md`, `agents/**/*.md`, `commands/**/*.md`, `skills/**/*.md`, `tsconfig.json`, `pyproject.toml`, `.golangci.yml`, `.yaml`, `.yml`, and `.md` generally. The list names the common non-owned source extensions because the task's scope is everything outside Go/Python/Node; adding or removing one later is a one-line trigger edit in the guide plus `make build-index` — not a command change.

4. **Duplicates are impossible on a language-only diff by construction; a mixed diff is contained by `Applies when`.** Because no trigger glob matches a language-owned extension, a Go/Python/Node-only diff never places a maintainability rule in the candidate set. On a mixed diff (`infra/main.tf` plus `pkg/order.go`) the maintainability rules are candidates, and each rule's `Applies when` confines the finding to the non-owned file — so the `.go` file is adjudicated only by its own family. AC5 locks that boundary, and AC6 proves the rules are not catch-alls.

5. **The owner agent exists and reads the guide.** `agents/maintainability-assistant.md` follows `docs/agent-command-development-guide.md`, names `docs/maintainability-review-guide.md` as its source of truth, adjudicates the five judgment rules over the changed non-owned files, and assigns severity (Must Fix / Should Fix / Nice to Have) to what it finds. It is registered in the `README.md` agents table and in `llms.txt`.

6. **The boundary is regression-locked.** Three fixture trees live under `specs/fixtures/maintainability/`: `terraform-shell-smells/` (a Terraform comment restating the code, a dead declaration, a shell `|| true` bandaid), `go-covered/` (a `.go` file hitting `go-errors/no-fmt-errorf` plus a comment restating the code), and `terraform-shell-clean/` (a non-owned change with none of the smells). `scripts/acceptance.sh` gains a block that runs the AC3 selector simulation over the Terraform/shell list and the owned-source list and asserts the first yields all five maintainability ids while the second yields none — so `make precommit` fails if a future trigger edit crosses the boundary.

7. **Ship readiness.** `rules/index.json` is regenerated (199 entries) and `make check-index` passes; CHANGELOG gains a `## Unreleased` section with a `feat:` bullet; `make precommit` exits 0 after every prompt; the `.maintainer.yaml` autoRelease tail is left to the releaser.

## Constraints

- **Rule identity:** all 5 new ids use the two-component `maintainability/<slug>` form, matching the existing non-language rule families (`self-containment/*`, `changelog/*`, `git-commit/*`). Every component is lowercase letters, digits and hyphens.
- **Owner:** `maintainability-assistant` in every new block and every index entry. `scripts/acceptance.sh` asserts every index owner has a matching `agents/<owner>.md`, so the agent file is mandatory, not documentation.
- **Schema contract (frozen):** field order Owner → Applies when → Enforcement → Trigger; `**Trigger**:` immediately after `**Enforcement**:` on every rule (all five are judgment-tier); `**Why**:` and `#### Bad` / `#### Good` follow, as `docs/rule-block-schema.md` requires.
- **Dedup invariant (frozen):** no maintainability trigger glob matches a file type owned by an existing rule family, enumerated in Desired Behavior 3. This is the only dedup mechanism — there is no adjudicator-side suppression rule and no candidate-set filter.
- **Whole-file scope, not diff-hunk scope:** the adjudicator is handed the diff, and Step 5's rule that only changed code is reportable is what drops a pre-existing smell on an untouched line. The guide states this.
- **One script edit only:** `scripts/build-index.py` already parses `Owner`, `Applies when`, `Enforcement`, `Trigger` and `Class`, so the guide plus `make build-index` is the entire integration; it does not parse `Why`. `scripts/acceptance.sh` is the only script edited, and only to add the AC3 assertion block.
- **Generic content only:** every Bad/Good example and fixture uses User, Order, Product, Customer — never trading or project-specific domains.
- **Vocabulary:** the guide cites `docs/code-smell-vocabulary.md` and reuses its terms (`dead code`, `speculative generality`); it defines no second vocabulary.
- **Self-Contained rule:** `coding/CLAUDE.md` forbids `~/.claude/` and `/Users/bborbe/` references in shipped plugin files; the guide, the agent and the fixtures use generic paths only.
- **Index freshness:** any prompt that edits a RULE block also runs `make build-index` and commits the result — `make check-index` fails otherwise.
- **Release tail:** `.dark-factory.yaml` sets `autoRelease: false`; the release is cut by the maintainer-agent-releaser per `.maintainer.yaml` (`autoRelease: true`) — out of band. This spec requires only the CHANGELOG `## Unreleased` entry.
- **Approval discipline:** never edit frontmatter status manually — approval goes through `dark-factory spec approve`.

## Security / Abuse Cases

The change adds rules an LLM adjudicator applies to untrusted changed files; it reads no new input, writes nothing, and executes nothing.

- **Attacker-controlled input:** the changed files of a consumer repo. The rules judge text and structure; they never execute the file and never treat its content as instruction.
- **Prompt-injection surface:** unchanged from the existing funnel — the diff is already untrusted quoted data.
- **Trust boundary:** no new read path; `build-index.py` reads only `docs/`, and the adjudicator reads only the diff and the rule blocks.
- **What can hang / retry forever / race:** nothing — the change is static data (rule blocks and a generated index). No network, no background work, no shared mutable state.
- **Input validation:** the 5 rule ids are validated by `build-index.py` (lowercase, ≥2 slash components, level token). `validate-citations.sh` resolves every new id against `rules/index.json`, so an invented rule cannot survive.

**Why one spec and one PR.** All five rules are one rule family with one owner, one guide and one trigger list; splitting them would multiply the release cycles the goal's serial-ship rule already constrains. The sibling changes under [[PR Reviewer Adopts What the Five-Lens Gate Got Right]] ship strictly one per bench re-run, so this change stays a single unit and takes exactly one bench run. The DB×AC count (7 × 12) exceeds the guide's split signal because the AC set is verification-heavy for a static-data change; the layers it touches are one artifact family (guide + rules + agent) plus its test lock, not independent code layers.

## Do-Nothing Option

If this does not ship, `/coding:pr-review` keeps returning essentially nothing on Terraform, shell and other non-Go/Python/Node changes — the 8-candidate selector output in the Problem section is the whole judgment tier for such a diff. [[PR Reviewer Adopts What the Five-Lens Gate Got Right]] closes SC5 on nothing, and the maintainability lens — the last unshipped item on the gate's ranked shortlist — stays unported. The cost of not doing this is that the reviewer's coverage remains a property of the repo's language, not of the change's quality.
