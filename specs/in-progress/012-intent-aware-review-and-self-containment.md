## Summary

- Add 5 self-containment rules to the shared rule base — 4 script-tier grep checks (`~/` and absolute home paths, requirement IDs, planning-doc references, revision/sign-off phrases) plus 1 judgment rule for steering echoes — all owner `self-containment-assistant`.
- Ship them as a new `docs/self-containment-guide.md` rule guide plus a matching `agents/self-containment-assistant.md`, so the judgment rule has an owner and the guide/agent alignment rule holds.
- Make `/coding:pr-review` intent-aware: a new `--intent <path>` / `--pr <n>` argument, an auto-detect fallback that reads the PR body, and an adjudication rule that a deviation the author stated and justified is a recorded decision, not a finding.
- Keep the intent input dormant when absent: with no stated intent the adjudicator behaves byte-for-byte as today and the report says so on its own line.
- Lock the script tier with committed fixtures asserted by `scripts/acceptance.sh`, so `make precommit` fails if a self-containment check stops firing or starts over-firing.

## Problem

`/coding:pr-review` and the [[GitHub PR Reviewer Agent]] are intent-blind. When an author states and justifies a deviation in the PR body — "kept the retry inline rather than extracting a helper, because the extracted version needed the request context" — the reviewer re-flags it as a finding anyway. The author's justification is on the record and the reviewer never reads it, so the operator learns to ignore findings and the report's precision reads worse than it is.

The same reviewer catches no leaked planning context. Agent-authored PRs are the main input to this funnel, and they routinely carry artifacts of how the change was planned rather than what it does: `~/` paths that only resolve on the author's machine, requirement IDs (`FR-1`, `NFR-3`, `SC-2`) that mean nothing in the repo, references to planning documents that will never be in the tree, revision meta ("revised after review") that describes the authoring process instead of the code, and comments that echo the instruction that produced them rather than explaining the code. Every one of these is a defect a human reviewer would flag, and the rule base has no rule for any of them.

Both gaps are ports from the [[Five-Lens Review Gate]] analysis: shortlist item 1 (self-containment lens) and item 2 (intent-vs-diff axis). The rule base is shared by `/coding:pr-review`, `/coding:local-review` and `/coding:code-review`, so the self-containment half lands in all three for free.

## Goal

The rule base carries 5 self-containment rules — 4 deterministic and 1 judgment — that fire on leaked planning context in any changed file, in every language, in all three review commands. A fixture diff containing a `~/` path and an `FR-` requirement ID produces both findings; a fixture containing neither produces none.

`/coding:pr-review` reads the change's stated intent before it adjudicates. When a diff's PR body states and justifies a deviation, the report carries no finding for that deviation and records it under `Notes:` as a stated decision; the same diff with the justification removed produces one. When no intent is available — no PR, no `gh`, no `--intent` — the command says `Intent: unavailable — <reason>` on its own report line and behaves exactly as it does today.

Neither half costs recall: the bench re-run after the change scores at or above the recorded baseline.

## Non-goals

- Do NOT add a `--intent` input to `/coding:local-review` or `/coding:code-review` — a local diff has no PR body, and the whole-codebase audit has no single change to state intent for.
- Do NOT add a fix loop or a re-review round — iteration belongs to the authoring workflow, not the reviewer.
- Do NOT port `design-decision-questioner` or the gate's fix-loop cap; the analysis rejected both.
- Do NOT change the `security-review` lens, the security pipeline, or the `--security` flag.
- Do NOT change `scripts/validate-citations.sh`, `.maintainer.yaml`, or any `scenarios/*.md`.
- Do NOT add a config knob, an opt-out flag, or a tunable severity to the self-containment rules — the rule `level` is the only acceptance surface.
- Do NOT narrow the script checks to diff hunks — the runner is handed a file list and no base ref by design; unchanged-line findings stay the adjudicator's filter to drop (see Constraints).

## Desired Behavior

1. **The guide exists and carries five rule blocks.** `docs/self-containment-guide.md` ships `### RULE self-containment/<slug> (LEVEL)` blocks for `no-home-dir-paths`, `no-requirement-ids`, `no-planning-doc-refs`, `no-revision-meta` and `no-steering-echoes`, each conforming to `docs/rule-block-schema.md` (Owner → Applies when → Enforcement, then `**Why**:` and `#### Bad` / `#### Good` examples using generic domains). The guide states what self-containment means, why agent-authored diffs leak planning context, and that the script tier scans whole changed files rather than diff hunks.
2. **Four script-tier rules fire deterministically.** `scripts/rule-checks.sh` gains one check per script-tier rule, each emitting a finding with the real `file` and `line` of the match: `no-home-dir-paths` (MUST) matches a `~/`-rooted path or an absolute `/Users/<name>/` / `/home/<name>/` path; `no-requirement-ids` (SHOULD) matches `FR-`, `NFR-` or `SC-` followed by a digit; `no-planning-doc-refs` (SHOULD) matches a reference to a planning *directory* (`specs/`, `prompts/`, `docs/plans/`) or planning prose ("the plan says", "as discussed"); `no-revision-meta` (SHOULD) matches revision and sign-off provenance ("revised per review", "as requested in the review", "signed off by", "v2 of this change"). The four patterns are pinned as `(^|[^A-Za-z0-9])~/[A-Za-z0-9._-]`, `/(Users|home)/[A-Za-z0-9._-]`, `\b(FR|NFR|SC)-[0-9]`, `\b(specs|prompts|docs/plans)/|the plan says|as discussed`, and `revised per|as requested in the review|signed off by|v[0-9]+ of this change` — and AC12's `<PATTERNS>` is these five, not a re-typed approximation, so the rule and its enforcement cannot drift apart. **Bare ticket ids are deliberately not a marker.** Any `[A-Z]+-<digits>` pattern collides with legitimate repo content (`ADR-0001` in `docs/adr-guide.md`, `BSD-2-Clause` in `docs/go-licensing-guide.md`, `GO-2026-*` in `CHANGELOG.md`), so a leaked `PROJECT-12345` is left to the judgment rule rather than bought with a false-positive surface the script tier cannot adjudicate away. Each check is diff-scoped to the changed-file list it is handed, skips `vendor/` and `node_modules/`, skips binary files, and evaluates its exemption **per changed file, inside the scan loop — never via the check-level `changed_file_matches` helper.** That helper returns true when *any* changed file matches, and every existing check uses it check-level; reusing it here would disable the rule for an entire run whenever a spec or prompt appears in the diff — that is, on nearly every dark-factory PR — silently neutering the feature while every AC still passed.

The exemption has two parts, both stated in the guide.

**Part one — six literal paths**, matched against the **absolute** path as `rule-checks.sh` normalises it, anchored at `$TARGET_DIR` (`"$TARGET_DIR"/specs/*`), never a bare `specs/*`: the script rewrites every changed-file argument to an absolute path before any check runs, so a repo-relative pattern matches nothing and the exemption would be silently inert in every real review. The six are `specs/` and `prompts/` (planning context *belongs* there — the rule catches it leaking out of them; the `.reviewignore` already excludes both from the pr-review path, but `/coding:local-review` and `/coding:code-review` build their file lists without consulting it, so the in-script exemption is what covers those two commands), `docs/self-containment-guide.md` and `agents/self-containment-assistant.md` (they must show the markers to teach the rule), `scripts/rule-checks.sh` (the regexes *are* the literals), and `scripts/testdata/self-containment/` (the fixtures).

**Part two — a constraint, not an exemption, because a path list cannot be exhaustive here.** No artifact outside those six may contain a marker literal. That is what covers `rules/index.json`: `build-index.py` copies the guide's `Owner` / `Applies when` / `Enforcement` field lines verbatim into the index, so those three lines are worded descriptively — "a home-directory path", never the path form — and the index inherits no literals. It equally covers the CHANGELOG bullet and any example added to `commands/pr-review.md`. The constraint is enforced by AC12 rather than trusted, and an author who genuinely needs a literal adds their artifact to the six — a closed set, not a glob a consumer repo can widen, and not a general "docs are exempt" rule.
3. **One judgment rule covers steering echoes.** `self-containment/no-steering-echoes` (SHOULD) is judgment-tier, owned by `self-containment-assistant`, carrying `**Trigger**: @commits` so it is always a candidate. It fires when a comment or identifier restates the instruction that produced the change rather than describing the code — the text answers "what was I asked to do", not "what does this do".
4. **The agent exists and reads the guide.** `agents/self-containment-assistant.md` follows `docs/agent-command-development-guide.md`, names `docs/self-containment-guide.md` as its source of truth, adjudicates the judgment rule over the changed files, and assigns severity to the script tier's findings. It is registered in the `README.md` agents table and in `llms.txt`.
5. **The script tier is regression-locked.** `scripts/testdata/self-containment/dirty/` holds a fixture file carrying every script-tier marker and `scripts/testdata/self-containment/clean/` holds one carrying none. `scripts/acceptance.sh` gains a block that runs `rule-checks.sh` over each and asserts the dirty fixture yields all four rule ids while the clean fixture yields zero — so `make precommit` fails if a check stops firing or starts over-firing.
6. **`/coding:pr-review` captures stated intent before adjudicating.** A new step runs after the diff is generated and before candidate computation. It resolves the intent from, in order: `--intent <path>` (read verbatim), `--pr <number>` (`gh pr view <n> --json title,body,comments --jq …`), the branch's own PR (`gh pr view <SOURCE_BRANCH> --json title,body`), or nothing. `--pr` exists because the agent pod's checkout is a **detached** worktree, where `git branch --show-current` is empty and the branch-name fallback cannot resolve the PR — it is the pod's way in, not a convenience. The step writes its result to a session-local artifact at the fixed path `/tmp/pr-review-intent-<repo>-<SOURCE_BRANCH>.json` (mirroring the existing `/tmp/pr-review-findings.json` convention), holding the stated intent text and the deviations the author explicitly stated *and* justified, or `{"intent": "unavailable", "reason": "<why>"}`. The step never fails the review: a missing `gh`, a missing PR, or an unreadable `--intent` path degrades to `unavailable` with the reason recorded. The command's frontmatter `argument-hint` gains both flags.
7. **The adjudicator consults intent, and the report says what it did.** Step 5 gains a mandatory line — `Intent: <source>` or `Intent: unavailable — <reason>` — and `docs/selector-mode-guide.md` gains `INTENT` in its `## Inputs` list plus a dormant `## Intent Extension (dormant)` section — an H2 sibling of the existing `## Security Extension (dormant)`, containing an `### Adjudicator input extension` subsection in the same shape — carrying the stated rule: a candidate whose subject is a deviation the author stated and justified is not emitted as a finding; it is recorded under `Notes:` as `Decision (stated intent): <what was stated>`. When `INTENT` is unset the guide's Step 4c-sel / 4d-sel run byte-for-byte as they do today — the same dormancy contract the security extension already uses. The intent input applies to `/coding:pr-review` only; `/coding:code-review` and `/coding:local-review` pass no `INTENT` and are unaffected.
8. **Ship readiness.** `rules/index.json` is regenerated (194 entries) and `make check-index` passes; CHANGELOG gains a `## Unreleased` section with a `feat:` bullet; `make precommit` exits 0 after every prompt; the `.maintainer.yaml` autoRelease tail is left to the releaser.

## Constraints

- **Rule identity:** all 5 new IDs use the two-component `self-containment/<slug>` form, matching the existing non-language rule families (`changelog/*`, `git-commit/*`, `skill-writing/*`). Every component is lowercase letters, digits and hyphens.
- **Owner:** `self-containment-assistant` in every new block and every index entry.
- **Schema contract (frozen):** field order Owner → Applies when → Enforcement; `**Trigger**:` immediately after `**Enforcement**:` on the one judgment rule and absent on all four script rules; script rules derive `enforcement_type: script` because their enforcement text cites `scripts/rule-checks.sh`.
- **Whole-file scope, not diff-hunk scope:** `rule-checks.sh` receives a file list and no base ref, so a self-containment check scans each changed file whole and can flag a pre-existing match on a line the diff never touched. This is the existing script-tier contract (Step 4a of `commands/pr-review.md` states it for the funnel generally); the guide documents it and the adjudicator's changed-line filter drops those findings. Narrowing to hunks would require passing a base ref into the runner and is out of scope.
- **Self-exemption — six literal paths, matched absolute, evaluated per file.** `specs/`, `prompts/`, `docs/self-containment-guide.md`, `agents/self-containment-assistant.md`, `scripts/rule-checks.sh`, `scripts/testdata/self-containment/`. Each pattern is anchored at `$TARGET_DIR` (`"$TARGET_DIR"/specs/*`), because `rule-checks.sh` rewrites every changed-file argument to an absolute path before any check runs — a repo-relative pattern matches nothing there and the exemption would be inert while looking correct. The check is applied **per changed file inside the scan loop**, never through `changed_file_matches`, whose any-file semantics would disable the rule for a whole run whenever a spec or prompt is in the diff.
- **No marker literals on any line this change adds, outside those six.** Change-scoped, not tree-scoped: the repo already carries literals in three guides this PR does not touch, so an absolute "no literals anywhere" claim would be false before the first commit and its AC would be permanently red. This is the constraint that closes the enumeration, and AC12 enforces it rather than trusting it. It is what keeps `rules/index.json` clean: `build-index.py` copies the guide's `Owner` / `Applies when` / `Enforcement` lines verbatim, so those three lines describe the markers in words ("a home-directory path") and never quote them. It equally binds the CHANGELOG bullet and any example added to `commands/pr-review.md`. An author who genuinely needs a literal adds their artifact to the six — the list is closed and stated in the guide, so the exception is auditable rather than discovered.
- **Assumption — the rule base is shared.** The self-containment half lands in `rules/index.json` and `scripts/rule-checks.sh`, which `/coding:pr-review`, `/coding:local-review` and `/coding:code-review` all run. That is what makes five rules worth a spec: one authoring pass covers three commands, and no command file needs editing for the self-containment half. The intent half is deliberately not shared (Non-goals).
- **The guide must pass the repo's own `Self-Contained` rule:** `coding/CLAUDE.md` forbids `~/.claude/` and `/Users/bborbe/` references in shipped plugin files, so the guide, the agent, and the fixtures use `~`-rooted and `/home/<user>/` forms and never a real operator path. Those three artifacts are exactly the ones the exemption covers — the constraint and the exemption are the same decision seen from two sides, which is why none of them may be dropped from the list.
- **No new ast-grep YAML:** all 5 rules are script- or judgment-tier, so `rules/` gains no YAML and `check-coverage.sh` sees no orphan.
- **Walker invariants:** `scripts/build-index.py` is unchanged — it already parses the three required fields, `Trigger`, and `Class`; output stays byte-stable and sorted.
- **Dormancy:** with no `INTENT`, `docs/selector-mode-guide.md`'s Step 4c-sel / 4d-sel run as they do today, and `/coding:code-review`'s and `/coding:local-review`'s invocations of the same guide pass no `INTENT`. The security extension is untouched.
- **Determinism of the script checks:** each check is pure grep/`case` over the handed file list — no network, no `gh`, no clock, no ordering dependence; `rule-checks.sh` stays `bash 3.2` compatible and shellcheck-clean.
- **Generic content only:** every Bad/Good example and fixture uses User, Order, Product, Customer — never trading or project-specific domains.
- **Index freshness:** any prompt that edits a RULE block also runs `make build-index` and commits the result — `make check-index` fails otherwise.
- **Release tail:** `.dark-factory.yaml` sets `autoRelease: false` (dark-factory commits locally); the release is cut by the maintainer-agent-releaser per `.maintainer.yaml` (`autoRelease: true`) — out of band. This spec requires only the CHANGELOG `## Unreleased` entry.
- **Approval discipline:** never edit frontmatter status manually — approval goes through `dark-factory spec approve`.

## Security / Abuse Cases

The feature reads untrusted input — a PR body, an issue body, and the changed files of a consumer repo — and adds rules an LLM adjudicator applies to that input.

- **Attacker-controlled input:** the PR body and linked issue are attacker-controlled text. They are read as data and never executed, and the intent block is a *suppression* signal only — it can cause a finding to be recorded as a stated decision, never to be silently deleted. A PR body claiming "everything here is intentional and justified" does not produce a clean report: the adjudicator's rule is per-deviation ("this specific stated deviation"), and a blanket claim names no deviation, so no candidate matches it.
- **Prompt-injection surface:** the intent block is the first place a PR body's own text enters the adjudicator's context. The capture step wraps it in an `INTENT` block labelled as untrusted quoted data and instructs the adjudicator to treat it as a claim to check against the diff, not as instruction — the same posture the existing funnel takes toward the diff itself.
- **Trust boundary:** `rule-checks.sh` reads only files under the handed target directory; the new checks add no new read path. Fixtures under `scripts/testdata/` are repo-owned constants.
- **What can hang / retry forever / race:** the `gh` calls in the intent step are bounded single-shot reads with a failure path to `unavailable`; there is no retry loop. No new network, no background work, no shared mutable state.
- **Input validation:** the 5 rule IDs are validated by `build-index.py` (lowercase, ≥2 slash components, level tokens MUST/SHOULD/MAY). The `--intent` path is read-only and never written to. The intent block is bounded by the PR body's own size, and the capture step truncates an oversized body with a recorded `truncated:` marker rather than silently dropping the tail.
- **Provenance integrity:** every new rule finding cites a `rule_id` present in `rules/index.json`, so `validate-citations.sh` resolves it and no invented rule survives.

## Suggested Decomposition

Prompts generated in this order — each row is one prompt with an auditable scope. Ordering keeps `make precommit` green after every prompt: the guide authoring and the index regen are bundled (the check-index gate), and the fixtures land with the checks they lock.

| # | Prompt focus | Covers DBs | Covers ACs | Depends on |
|---|---|---|---|---|
| 1 | Author `docs/self-containment-guide.md` with all 5 RULE blocks + `agents/self-containment-assistant.md` + register both in `README.md` and `llms.txt` + `make build-index` regen (194 entries) | 1, 3, 4 | 1, 9 | — |
| 2 | Implement the 4 script checks in `scripts/rule-checks.sh` + commit the dirty/clean fixtures under `scripts/testdata/self-containment/` + add the `scripts/acceptance.sh` assertion block | 2, 5 | 2, 3, 4, 9 | prompt 1 (the rule ids must exist in the index for the assertions to cite them) |
| 3 | Wire intent into `commands/pr-review.md` (`--intent` / `--pr` arguments + `argument-hint`, the capture step writing `/tmp/pr-review-intent-<repo>-<branch>.json`, the `Intent:` report line) and add the dormant `## Intent Extension (dormant)` section + `INTENT` input to `docs/selector-mode-guide.md` | 6, 7 | 5, 7 | — |
| 4 | CHANGELOG `## Unreleased` feat entry + final cross-cutting gates (`make precommit`, the negative scope-lock ACs, citation validation over the new ids) | 8 | 8, 9, 10 | prompts 1, 2, 3 |

Rationale: prompt 1 is documentation-plus-index and touches no script, so it can land first with the index gate green. Prompt 2 is the only prompt that writes `scripts/rule-checks.sh`, keeping that file single-writer. Prompt 3 is independent of both — it touches only `commands/` and `docs/selector-mode-guide.md` — so it can run in parallel or after. Prompt 4 is the release tail. AC6, AC7 and AC11 are operator-executable (they need the released plugin and the bench) and are covered by the Verification operator rung, not by a prompt.

**Why one spec and one PR, not two.** The parent goal's doctrine is "one change at a time with a [[PR Review Bench]] re-run between each", which reads as an argument for splitting the self-containment half from the intent half. It is deliberately not split here, on an asymmetry: the self-containment rules can only *add* findings, and recall is scored against a fixed golden set of expected findings, so they cannot lower it. Only the intent step suppresses findings, so only it can move recall. A recall drop therefore attributes to the intent half by construction, and one bench re-run carries the verdict for both. Splitting would buy no additional attribution and cost a second release cycle and a second bench run. The operator confirmed this reading before the spec was approved.

## Do-Nothing Option

If this does not ship, `/coding:pr-review` keeps re-flagging deviations the author already stated and justified, which is the logged weakness that teaches the operator to skim its findings, and no rule in the 189-entry base catches a leaked `~/` path, a dangling `FR-4`, or a comment that restates the instruction that produced it. The goal [[PR Reviewer Adopts What the Five-Lens Gate Got Right]] closes SC1 and SC2 on nothing, and the two shortlist items its analysis ranked first and second — the cheapest and most deterministic of the five — stay unported. The current approach is not acceptable: the techniques are already analysed, ranked and fixture-shaped, so the remaining cost is authoring, not discovery.
